Using Rose SSO in Laravel

Connect Laravel eSigned to Keycloak realm jathnier using client esigned. Employees authenticate with Keycloak; their existing application accounts, documents, roles, and permissions remain in eSigned. The managed employee attribute idcode establishes an account link.

For Laravel developers integrating an application with the existing Rose SSO service.

This is a reference implementation, not confirmation of deployed changes. The Laravel project has not been inspected. Adapt examples to its framework version, authentication guard, employee relationships, and account eligibility rules. The examples assume App\Models\User, the web guard, and users.idcode.

2 Login flow

  1. An employee selects Sign in with SSO in eSigned.
  2. Laravel redirects the browser to Keycloak with session-bound state and PKCE.
  3. Keycloak authenticates the employee and returns an authorization code.
  4. Laravel exchanges the code and requests UserInfo over HTTPS.
  5. Laravel resolves an existing identity link, or matches exactly one eligible employee by idcode and records their Keycloak issuer and subject.
  6. Laravel creates its normal session. Existing application permissions still control document access, signing actions, and administrator actions.

This does not automatically synchronize employees, create accounts, or grant roles.

3 Prerequisites from your SSO administrator

Before implementing Laravel login, obtain your application client ID, client secret, realm URL, and approved HTTPS callback URL. Ask your SSO administrator to confirm that the client supports the authorization code flow with S256 PKCE and returns sub plus a single string idcode in UserInfo.

Keep employee codes as strings, including leading zeros. Confirm that codes are unique and managed by authorized administrators; do not allow an employee to change the code used for account linking. The Laravel examples below consume these existing settings.

Quote the secret according to dotenv syntax if its characters require it. SSO_ENABLED and SSO_IDCODE_CLAIM are custom application settings defined below, not built-in Laravel features. Use persistent session storage and a cookie name unique to eSigned. Prefer host-only cookies. Coordinate cookie changes because existing sessions may end.

Add this entry inside the returned array in config/services.php:

'keycloak' => [
    'client_id' => env('KEYCLOAK_CLIENT_ID'),
    'client_secret' => env('KEYCLOAK_CLIENT_SECRET'),
    'redirect' => env('KEYCLOAK_REDIRECT_URI'),
    'base_url' => env('KEYCLOAK_BASE_URL'),
    'realms' => env('KEYCLOAK_REALM'),
],

The provider's key is realms, while the environment variable is singular. Create config/sso.php:

<?php

return [
    'enabled' => env('SSO_ENABLED', false),
    'idcode_claim' => env('SSO_IDCODE_CLAIM', 'idcode'),
];

For Laravel 11 and later, merge this listener into the existing boot() method in app/Providers/AppServiceProvider.php:

\Illuminate\Support\Facades\Event::listen(
    \SocialiteProviders\Manager\SocialiteWasCalled::class,
    function ($event) {
        $event->extendSocialite(
            'keycloak',
            \SocialiteProviders\Keycloak\Provider::class
        );
    }
);

For Laravel 10 and earlier, add this entry once to the existing $listen array in app/Providers/EventServiceProvider.php instead:

\SocialiteProviders\Manager\SocialiteWasCalled::class => [
    \SocialiteProviders\Keycloak\KeycloakExtendSocialite::class . '@handle',
],

Follow the Manager installation instructions for service-provider registration on the installed version. Ensure its Manager service provider is registered, without duplicate managers or event listeners. Provider reference: Keycloak adapter setup.

Audit missing and duplicate codes and enforce uniqueness in the database where business rules permit. Check case and whitespace comparisons; deny ambiguous matches.

Create a reviewed migration for identity columns. For a conventional users table, the schema fragment is below. Add normal migration imports and rollback:

Schema::table('users', function (Blueprint $table) {
    $table->string('keycloak_issuer', 191)->nullable();
    $table->string('keycloak_subject', 191)->nullable();
    $table->unique(
        ['keycloak_issuer', 'keycloak_subject'],
        'users_keycloak_identity_unique'
    );
});

Review nullable unique-index behavior for the actual database engine. Preserve existing user IDs and document ownership. Cast is_active as boolean in the model or replace the example's eligibility rule. Missing flags deliberately deny login.

An existing issuer and subject link takes precedence over code matching. Never silently relink a user because a code changed. Recreated Keycloak users, reused employee records, and soft-deleted accounts require administrator review.

6 Login callback and logout controller

Create app/Http/Controllers/Auth/KeycloakController.php. Adapt the model, employee lookup, eligibility check, login error page, and landing page to the application. The code below deliberately rejects missing or ambiguous identities.

<?php

namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use App\Models\User;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Log;
use Laravel\Socialite\Facades\Socialite;
use Throwable;

class KeycloakController extends Controller
{
    public function redirect()
    {
        abort_unless(config('sso.enabled'), 404);

        return Socialite::driver('keycloak')
            ->scopes(['openid', 'profile', 'email'])
            ->enablePKCE()->redirect();
    }

    public function callback(Request $request)
    {
        abort_unless(config('sso.enabled'), 404);

        try {
            $remote = Socialite::driver('keycloak')->enablePKCE()->user();
        } catch (Throwable $error) {
            // Exception messages can contain token responses; omit them here.
            Log::warning('SSO callback failed', [
                'exception_type' => get_class($error),
            ]);

            return redirect('/login')->withErrors([
                'sso' => 'SSO could not complete. Please try again.',
            ]);
        }

        $raw = $remote->getRaw();
        $code = $raw[config('sso.idcode_claim')] ?? null;
        $subject = $remote->getId();
        $issuer = rtrim(config('services.keycloak.base_url'), '/')
            . '/realms/' . config('services.keycloak.realms');

        abort_unless(
            is_string($code) && $code !== '' && trim($code) === $code
            && is_string($subject) && $subject !== '',
            403,
            'Your SSO account is not eligible for eSigned.'
        );

        $user = DB::transaction(function () use ($issuer, $subject, $code) {
            $user = User::where('keycloak_issuer', $issuer)
                ->where('keycloak_subject', $subject)
                ->lockForUpdate()->first();

            if (!$user) {
                $matches = User::where('idcode', $code)
                    ->lockForUpdate()->limit(2)->get();

                abort_unless($matches->count() === 1, 403,
                    'Your account is not eligible for eSigned.');

                $user = $matches->first();

                abort_unless(
                    $user->keycloak_issuer === null
                    && $user->keycloak_subject === null,
                    403,
                    'Contact support to review your account link.'
                );
            }

            // Replace with all existing account eligibility checks.
            abort_unless(
                $user->getAttribute('is_active') === true
                && (string) $user->idcode === $code,
                403,
                'Your account is not eligible for eSigned.'
            );

            if ($user->keycloak_subject === null) {
                $user->keycloak_issuer = $issuer;
                $user->keycloak_subject = $subject;
                $user->save();
            }

            return $user;
        });

        Auth::guard('web')->login($user);
        $request->session()->regenerate();

        // Replace with eSigned's actual fixed local landing page.
        return redirect('/');
    }

    public function logout(Request $request)
    {
        // Sign out of eSigned only; preserve the shared Rose SSO session.
        Auth::guard('web')->logout();
        $request->session()->invalidate();
        $request->session()->regenerateToken();

        return redirect('/login');
    }
}

Keep the identity unique constraint to protect concurrent linking attempts. Handle any resulting conflict as a generic denied or failed login; never retry by attaching a different user. Local accounts are linked rather than recreated.

This adapter checks state, exchanges the code on the server, and requests UserInfo from the fixed HTTPS realm. The stored issuer is derived from server configuration, not the browser. Keep TLS verification enabled. If a different library consumes ID tokens directly, it must validate signature, issuer, audience, expiry, and any applicable nonce before trusting the claims.

Do not add stateless() to these browser routes. The session must retain state and the PKCE verifier from redirect to callback. Do not log codes, client secrets, full claims, or token responses.

References: Laravel Socialite, Socialite state and PKCE, Laravel session authentication.

7 Routes and user interface

Merge these routes into routes/web.php without replacing existing routes:

use App\Http\Controllers\Auth\KeycloakController;
use Illuminate\Support\Facades\Route;

Route::middleware('guest:web')->group(function () {
    Route::get('/auth/keycloak/redirect', [KeycloakController::class, 'redirect'])
        ->name('sso.redirect');
    Route::get('/auth/keycloak/callback', [KeycloakController::class, 'callback'])
        ->name('sso.callback');
});

Route::post('/auth/keycloak/logout', [KeycloakController::class, 'logout'])
    ->middleware('auth:web')->name('sso.logout');

The web middleware stack must provide sessions. Retain CSRF protection on the logout POST. Confirm /login exists for callback failures and replace the controller's landing page with the correct local page. Do not place these routes in a stateless API group.

On the existing login page, show Sign in with SSO only when config('sso.enabled') is true and link it to route('sso.redirect'). Display the sso validation error using the application's normal error component. For logout, use a POST form targeting route('sso.logout') with Blade @csrf. Keep existing password login available for the pilot.

This logout flow invalidates only the local eSigned session. It does not open Keycloak logout or revoke the shared Rose SSO session. Selecting Rose SSO again can reuse the central session without another password prompt when that session and its browser cookies are still valid. Do not force prompt=login or max_age=0 for an ordinary sign-in. Keycloak policies may still require reauthentication.

For a Vue SPA, restore the user from the authenticated session endpoint on direct visits to home and login. Keep home accessible while signed in and show a permission-appropriate Go to dashboard link. If a valid session visits /login, redirect to an existing, permitted local intended page or the normal application landing page. Do not start a new SSO flow merely to visit home or /login. Preserve existing authorization checks and reject external redirects.

A logout or account disable in Keycloak alone does not automatically destroy every existing Laravel session. Immediate central revocation requires a separate backchannel logout or session revalidation implementation and tests.

9 Employee instructions

  1. Open https://esigned.rosebakeshop.net/ and select Sign in with SSO.
  2. Use your assigned Keycloak username and password, then complete any password update or MFA prompt.
  3. After successful login, your existing eSigned account opens.
  4. If access is denied, ask support to review your employee code and eligibility. Do not create another account to bypass the error.
  5. Use Sign out to leave eSigned. This does not sign you out of Rose SSO or other applications. On a shared computer, also use your organization's approved central SSO sign-out procedure and close the browser.

Adding idcode does not make it the login username. If employees should type their code into Keycloak's login page, provision their Keycloak username as that code under an agreed username policy. Account linking still uses idcode.

11 Laravel rollout and rollback

Back up the application database, including identity links, before applying migrations. Keep existing password login available during the pilot and deploy reviewed migrations and the Composer lock file through the normal release process.

To disable new SSO logins, set SSO_ENABLED=false and run php artisan config:cache. Retain existing password login and identity-link data. Disabling the entry point does not invalidate existing sessions; follow your application's session-revocation policy if needed. Do not delete users, documents, or signing records during rollback.

Before applying the examples, confirm the actual Laravel version, authentication model and guard, employee code relationship, account eligibility rules, login and landing routes, database engine, and approved linking policy.
